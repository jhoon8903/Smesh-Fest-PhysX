Dependency Map

실행 의존 구조

화살표는 현재 코드의 직접 호출·주입 관계입니다. Controller만 View와 Model을 알고, Transform·속도·충돌의 런타임 권위는 Rigidbody 하나로 유지합니다.

MVC 방향: Pool clone은 DI 직후, OnPoolCreated 전에 Registry가 View에 Model과 Controller를 한 번 조립합니다. Controller만 View와 Model을 참조하고 Model 변경 관찰을 담당합니다. View는 Unity 활성/파괴·Pool·충돌 이벤트만 발행하며 Model/Controller를 참조하지 않습니다. Model도 View/Controller를 참조하지 않습니다. 구형 호환 또는 fallback 없이 하나의 계약으로 구성했습니다.

Authority & Lifecycle

물리 권위와 재사용 경계

Model은 위치·속도를 복제하지 않습니다. 한 번의 대여를 epoch로 식별해 이전 사용의 늦은 콜백이 새 Ball/Obstacle을 건드리지 못하게 합니다.

두 가지 궤적, 하나의 Rigidbody 권위

Straight

Muzzle→hit point 방향으로 일정 속도로 비행합니다. 처음에는 중력을 OFF로 두고, 직접 Obstacle 충돌 또는 world Z 경계 통과 시 ON으로 전환합니다.

v = normalize(target − muzzle) × speed
Curve · fixed time

Config의 고정 비행시간 T로 초기속도를 계산하고, 발사 순간부터 동일한 중력을 적용합니다.

v = Δp / T − ½gT

현재 lease 검증·version 무효화 → OnPoolReturn → 상태/표현 초기화 → Pool root 재부모화 → inactive 보관 순으로 처리합니다. MinPool을 남기고 오래된 비활성 재고만 정리합니다.

계층 선파괴 · 신규 방어 분기

OnDestroy가 먼저면 현재 Pool entry와 version만 무효화·제거합니다. OnPoolReturn, 재부모화, 이중 Destroy는 실행하지 않습니다.

의미: Unity가 이미 파괴 중인 GameObject를 소유합니다. 따라서 선파괴는 재사용 경로가 아니라 씬 종료 방어 경로이며, Pool count도 해당 엔트리 제거 시점에 즉시 정합성을 회복합니다.
