# 프로젝트 시작 전 절차와 검토표

이 문서는 스킬 준비·프로젝트 시작안 준비 모드에서 읽는다. 사용자 목표와 구현 순서를 정리하되, 사용자가 어느 프로젝트를 어디서 시작하는지 볼 수 있어야 한다.

## 실행 순서

1. **현재 요청의 범위를 말한다.** 스킬 준비, 특정 프로젝트 시작안, 실제 생성/시작, 기존 작업 계속 중 무엇인지 구분한다.
2. **목적과 제약을 정리한다.** 기존 대화에서 답한 내용은 다시 묻지 않는다. 중요한 미결정만 질문한다.
3. **대상과 위치를 제안한다.** 이름, 새로 생성/기존 사용, 절대 경로, 현재 존재 여부를 보여준다. 경로를 주지 않았다면 제안으로 표시한다. 후보 폴더 발견만으로 시작 대상으로 지정하지 않는다.
4. **기획과 제작 단위를 제안한다.** 대표 플레이, 첫 완료 범위, 제외/후속 항목, 재사용 후보, 필요한 의존성을 정리한다. 비용이 큰 기획·기술 결정의 선택 이유와 반대안을 설명한다.
5. **함께 할 작업을 나눈다.** 사용자가 직접 할 일, AI가 맡을 일, 함께 확인할 결과를 정한다. 그다음 필요한 AI 보조 역할과 문서 순서를 제시한다. 전체 제작을 AI에게 위임했다고 가정하지 않는다.
6. **하나의 시작 검토표로 묶는다.** 문서가 필요한 경우 합의된 준비 문서 공간에만 저장한다. 위치가 합의되지 않았다면 먼저 대화에서 검토표를 제시한다. 검토표 작성을 이유로 대상 프로젝트 폴더를 생성하지 않는다.
7. **시작 결정에 맞춰 행동한다.** 이미 명시된 시작 결정은 재확인하지 않는다. 준비만 요청했다면 여기서 준비물을 전달한다. 시작이 승인됐다면 정확한 경로와 범위로 초기화하고 실제 생성 결과를 알린다.

## 시작 검토표 양식

아래는 양식이며 실제 경로·선택을 채우기 전에는 실행 지시가 아니다.

| 항목 | 기록할 내용 |
|---|---|
| 현재 모드 | 스킬 준비 / 시작안 검토 / 시작 승인 / 제작 중 |
| 목적 | 무엇을 누구에게 보여주거나 검증할지 |
| 프로젝트명 | 사용자 지정 또는 제안 표시 |
| 사용 방식 | 새로 생성 / 기존 프로젝트 사용 / 미정 |
| 프로젝트 절대 경로 | 실제 절대 경로 또는 미정 |
| 위치 상태 | 경로만 제안 / 사용자 확정 / 이미 존재함 |
| 준비 문서 위치 | 프로젝트와 구분되는 저장 위치 또는 대화 초안 |
| 생성·수정할 첫 파일 | 엔진 폴더, 문서, 소스 등의 구체 목록 |
| 보존할 기존 작업 | 수동 씬, Prefab, 설정, 병행 작업 |
| 승인된 핵심 루프 | 사용자 결정의 출처 |
| 첫 제작 범위 | 대표 플레이와 완료 기준 |
| 후속/미정 | 아직 이번 제작에 포함되지 않은 것 |
| 기술·재사용 | 엔진, 설치된 기반, 신규 의존성 제안 |
| 사람이 직접 할 일 | 사용자가 맡을 기획·코드·씬·UI·플레이 조정 |
| AI가 맡을 일 | 이번 단위에서 위임된 조사·구현·검증·기록 |
| 함께 확인할 결과 | 작은 실행물과 피드백 기준, 그 결과에 달린 다음 작업 |
| 작업량 운영 | 가용 시간과 이미 정한 비용 제약, 이번에 필요한 조사·에이전트 범위 |
| 검증 환경 | Editor/실기기/빌드와 실행 담당 |
| 자동 문서화 | 문서 원본과 갱신 시점 |
| 시작 결정 | 미요청 / 사용자 보류 / 승인, 관련 메시지 |
| 다음 행동 | 준비 전달 / 검토 반영 / 승인된 초기화 |

‘A안이 좋다’는 핵심 루프 선호이며 프로젝트 위치·생성/변경 시작 결정을 대신하지 않는다. 반대로 사용자가 이미 ‘지정한 경로에서 이 범위로 만들어’라고 했다면 명시된 범위는 승인되어 있으므로 사소한 단계별 승인을 추가하지 않는다.

## 시작 후 첫 작업

사용자에게 확인된 절대 경로를 알린 다음, 해당 경로의 기존 상태를 점검한다. 새 생성 경로가 이미 있다면 새로 덮어쓰지 말고 재사용 여부를 확인한다. 승인된 첫 파일만 생성하고, 생성·재사용 결과와 문서 위치를 보고한다.

이후 `SKILL.md`의 프로젝트 시작 후 시퀀스를 따른다. 에이전트를 배정할 때도 시작 결정·대상 경로·소유 파일을 함께 전달한다.
