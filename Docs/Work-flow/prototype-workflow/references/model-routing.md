# 모델·Effort 배정 정책

이 프로젝트의 Main Context는 사용자 선택에 따라 **Astra · Ultra**로 둔다. 보조 작업은 아래 기준으로 배정한다. 이는 초기 운영 기준이며, 비용 절감이나 품질 최적화가 측정으로 입증된 상태는 아니다.

모델 지원과 설정 형식 확인일: 2026-09-08. 다른 환경에서는 그 환경의 지원 목록과 실제 적용 상태를 다시 확인한다.

## 역할별 초기값

| 역할 | Model | Effort | 맡길 작업 |
|---|---|---|---|
| Main Context | `gpt-6-astra` | `ultra` | 사용자와 목표·분담 조율, 중요한 설계 판단, 결과 통합 |
| 자료 확인 `prototype_reader` | `gpt-5.6-luna` | `low` | 지정 파일에서 사실 추출, 목록·링크·문서 일치 확인 |
| 제작 `prototype_builder` | `gpt-5.6-terra` | `medium` | 합의된 설계의 작은 구현, 필요한 테스트, 문서 초안 |
| 복잡한 검토 `prototype_reviewer` | `gpt-5.6-sol` | `high` | PhysX 비교 조건, 셰이더·수명주기·상태 전이의 오류 검토 |
| 자동 보고서 생성 | 모델 없음 | 없음 | 기존 기록 스크립트로 이벤트 저장·보고서 갱신 |

일반 보조 작업의 기본값은 Terra · Medium이다. 단순 확인에는 Luna · Low를 명시한다. 여러 파일의 실행 흐름을 추적해야 하는 탐색도 Terra · Medium으로 시작한다. 가벼운 변경마다 Sol 리뷰를 추가하지 않는다. 보조 작업에 Astra 또는 Ultra를 사용하지 않는다.

## 오케스트레이터의 배정 순서

1. 이번에 함께 확인할 결과와 사용자/AI 분담을 먼저 정한다. 에이전트 수부터 정하지 않는다.
2. 짧은 수정·기록 호출은 메인이 직접 처리한다. 독립된 작업을 맡겨 메인과 병행할 이익이 있을 때만 위임한다.
3. 입력 경로, 허용된 변경 파일, 완료 기준이 명확한 작업 하나에 역할과 모델·Effort를 붙인다.
4. 필요한 파일과 결정 요약만 전달한다. 전체 대화 복제를 기본값으로 쓰지 않는다. 근거 원문과 실행 로그는 파일로 남기고 반환은 결론·근거·미완료 위주로 짧게 받는다.
5. 보조 에이전트는 기본 최대 2개를 동시에 사용한다. 환경의 한도가 더 작으면 그 한도를 따른다. 하위 에이전트의 재위임은 사용하지 않는다.
6. 메인은 결과의 완료 기준을 확인하고 사용자와 다음 작업을 정한다. 이미 근거가 있는 조사를 같은 범위로 다시 하지 않는다.

## 실패와 상향 기준

- 누락된 입력·불분명한 목표는 먼저 보완한다. 모델을 바꾸어 추측시키지 않는다.
- 범위가 명확한데도 요구를 빠뜨리거나 검증에 실패하면, 실패 근거와 함께 작업을 더 좁혀 한 번 상향할 수 있다. Luna · Low → Terra · Medium, Terra · Medium → Sol · High를 사용한다.
- 한 작업의 모델 상향은 최대 한 번이다. 이후에도 해결되지 않으면 결과와 실패 근거를 메인으로 돌려보내 직접 판단한다. Sol 작업을 Astra 보조 에이전트로 넘기지 않는다.
- 파일 접근·컴파일 도구·Unity 실행 환경의 부재는 모델 상향으로 해결하지 않는다. 필요한 환경이나 사람의 작업을 구분한다.
- 새 환경에서 해당 모델을 쓸 수 없으면 지원 목록을 확인한다. 같은 역할을 감당할 대체 설정을 명시하고 기록한다. 상위 모델을 조용히 상속시키지 않는다. 적절한 보조 모델이 없으면 메인이 작은 범위로 순차 처리하고 제한을 알린다.

## 실제 도구 호출

현재 세션의 `collaboration.spawn_agent`에서는 `model`과 `reasoning_effort`를 **둘 다 명시**한다. `fork_turns: "all"`은 상위 설정을 상속하며 모델 재정의와 함께 사용할 수 없으므로, 기본은 `"none"`이다. 필요한 문맥은 작업 메시지에 넣는다. 제한된 이전 대화가 필요하면 도구가 지원하는 작은 양만 전달한다.

다음은 형식 예시이며, 파일 경로·질문·범위를 실제 작업에 맞게 채운 뒤 호출한다.

```json
{
  "task_name": "check_record_schema",
  "agent_type": "explorer",
  "model": "gpt-5.6-luna",
  "reasoning_effort": "low",
  "fork_turns": "none",
  "message": "작업 ID, 실제 입력 경로, 확인할 질문, 변경 금지 범위와 반환 기준을 여기에 명시한다. 추가 에이전트를 만들지 않는다."
}
```

현재 도구의 역할 이름은 `explorer`, `worker`, `default` 등을 사용한다. 아래 커스텀 역할은 해당 환경이 로드하여 호출 가능한 목록에 나타날 때 사용한다. 다른 실행 도구에서는 그 도구의 실제 스키마를 확인하며 필드 이름을 임의로 옮기지 않는다.

## Git으로 옮기는 설정 템플릿

템플릿은 **현재 Docs 안에 보관 중이며 활성 설정에 설치하지 않았다.** 게임 제작 시작과 설정 적용은 별개다. 다음 설정 작업 때 기존 값을 비교해 필요한 항목만 병합한다.

| 저장소 안의 원본 | 적용할 프로젝트 위치 |
|---|---|
| [codex/config.toml](../codex/config.toml) | `.codex/config.toml` |
| [prototype_reader.toml](../codex/agents/prototype_reader.toml) | `.codex/agents/prototype_reader.toml` |
| [prototype_builder.toml](../codex/agents/prototype_builder.toml) | `.codex/agents/prototype_builder.toml` |
| [prototype_reviewer.toml](../codex/agents/prototype_reviewer.toml) | `.codex/agents/prototype_reviewer.toml` |

개인 경로·인증정보·권한 설정은 템플릿에 넣지 않는다. 기존 `.codex` 폴더 전체를 덮어쓰지 않는다. `agents/openai.yaml`은 스킬 표시 정보이며 이 모델 배정 설정과 다르다.

설정 파일에서는 `model_reasoning_effort`, 현재 위임 도구에서는 `reasoning_effort`를 쓴다. 커스텀 에이전트 파일의 모델·Effort는 생성 인자보다 우선할 수 있으므로 상향할 때는 새 등급의 역할을 사용한다. 예를 들어 reader 역할에 Terra 인자만 덧붙여 상향했다고 가정하지 않는다. 로드 후 실제 실행 환경의 모델 지원과 적용 상태를 확인한다. [공식 하위 에이전트 설정 문서](https://learn.chatgpt.com/ko-KR/docs/agent-configuration/subagents)

## 기록으로 확인할 것

배정 시 모델·Effort·선택 이유·문맥 범위, 종료 시 결과·검증·재작업 여부를 같은 작업 ID로 연결한다. [기록 방법](recording.md)의 메타데이터를 사용하며 모델이 별도로 보고서를 재작성하지 않는다.

- 배정값과 실제 적용 확인값을 구분한다. 도구가 호출을 수락했다는 사실을 실제 토큰 사용량 확인으로 확대하지 않는다.
- 환경이 제공하는 토큰·시간·사용량만 기록한다. 값이 없으면 미제공으로 남긴다.
- 합의한 결과의 완료율·재작업·관측 경과시간을 보고 다음 배정을 조정한다. 저렴한 모델에 여러 번 재시도한 비용도 포함한다.
- 절감률은 비교 가능한 기준과 실제 사용량이 있을 때만 계산한다. Codex 계정 한도와 API 가격을 같은 비용 지표로 취급하지 않는다.
