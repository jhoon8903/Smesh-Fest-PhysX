# 문서 계약

기존 기획·인계 문서가 있으면 해당 경로를 재사용한다. 아래는 처음 시작할 때의 기본값이다. 같은 결정은 여러 파일에 복제하지 않는다.

## 시작 전과 후의 문서 위치

스킬/흐름 준비에서는 스킬의 GUIDE·시작 검토표 양식·역할 문서를 작성한다. 특정 프로젝트 시작안은 합의된 준비 문서 위치 또는 대화에서 제시한다. 아래 프로젝트 문서 구조를 만든다는 이유로 미승인 프로젝트를 초기화하지 않는다.

아래 제작 기록은 프로젝트 시작 후 `Docs/Prototype/`를 기준으로 배치하고, HANDOFF는 `Docs/HANDOFF.md`에 둔다. 현재의 `Docs/Work-flow/` 스킬 문서 보관과 게임 구현 시작은 별도다. 기존 원본이 있다면 우선 재사용한다.

| 문서 | 원본으로 관리할 내용 | 갱신 시점 |
|---|---|---|
| BRIEF.md | 사용자 요청, 목표·기한, 확정 제약, 출처, 열려 있는 질문 | 최초 요청·사용자 방향 수정 |
| DESIGN.md 또는 기존 GDD | 대표 플레이·규칙·최소 범위·핵심 가설·사용자 결정 | 기획과 변경 결정 |
| PLAN.md | 작업 ID·의존성·소유 파일·재사용 판단·완료 증거·상태 | 작업 배정·통합 |
| REVIEW.md | 실제 검사와 조건·결과·원자료 링크·남은 검증 | 검사 직후 |
| evidence/events.jsonl | 기록기가 남기는 시각·담당·단계·증거 해시의 누적 이벤트 | 작업 시작/종료·변경·검증 |
| evidence/REPORT.md | 기록에서 자동 생성되는 한국어 보고서 | 기록기 호출 시마다 |
| 기존 HANDOFF 또는 Docs/HANDOFF.md | 현재 상태, 다음 행동, 결정·수동 작업 보존, 로드 순서 | 작업 종료·중요한 재개 지점 |

기존 기획이 충분한 경우 BRIEF/DESIGN을 빈 양식으로 추가하지 않는다. WORKFLOW.md는 사용자가 역할/시퀀스 문서를 요청할 때만 추가하며 스킬 설명을 통째로 복사하지 않는다.

## 상태와 출처

- `[FACT]` 실제 확인한 파일·실행·공식 자료. 조사 시각과 경로/URL을 붙인다.
- `[DECISION:user]` 사용자가 선택한 사항. 요청의 짧은 인용 또는 위치를 붙인다.
- `[DECISION:agent]` 되돌리기 쉬운 운영·구현 선택과 이유.
- `[PROPOSAL]` 승인받지 않은 기획·기술안.
- `[HYPOTHESIS]` 플레이/측정으로 판정할 가정.
- `[OPEN]` 질문, 답변 주체, 해당 답 없이는 진행할 수 없는 작업.

핵심 요구에는 R-001 같은 ID, 작업에는 W-001, 검증에는 V-001을 사용해 `요구 → 작업 → 검증`을 링크한다. ID 체계를 위한 별도 데이터베이스는 만들지 않는다.

## 검증 기록 최소 내용

검증 ID, 대상 요구/작업, 실행 일시, 실제 실행자, 도구/버전/빌드·기기, 입력/조건, 기대 결과, 관측 결과, 원자료, 미실행 항목.

상태는 `미실행 / 통과 / 실패 / 일부 확인`을 구분한다. 소스 검토만으로 Play Mode 또는 모바일 성능을 통과 처리하지 않는다. 사용자 실행 결과를 받으면 사용자 제공 증거로 표시한다.

## 생산성 보고서 해석

요청 대비 전달한 기능, 단계별 경과시간, 최초 실행 가능 빌드의 증거, 변경 요청 하나의 처리 기록, 재사용 범위, 사용자/AI 역할을 읽을 수 있게 한다. 사용자가 직접 만든 결과와 함께 검토해 바꾼 결정도 구분한다. 기록 시작 전 준비시간은 미측정이다. 대기·동시 작업을 포함하는 경과시간을 순수 작업시간으로 바꾸지 않는다. AI 사용 전 기준선이 없으면 절감률은 미측정으로 둔다.

작업 계획에는 사람 담당·AI 담당·함께 확인할 결과를 둔다. 매 대화를 새 문서로 늘리지 않고 결정·변경·검증만 관련 절에 누적한다.

REPORT.md는 생성 파일이며 직접 손으로 수정하지 않는다. 설명을 보강하려면 근거를 갖춘 새 이벤트를 기록한다. BRIEF/DESIGN/PLAN/REVIEW/HANDOFF는 에이전트가 실제 작업과 함께 편집하는 살아 있는 문서다. 기록기는 파일을 해시하고 보고서를 만들지만 게임의 성공 여부를 추론하지 않는다.

## 인계

현재 목표/성숙도, 완료물, 실제 검증, 미완료, 다음 행동, 승인된 결정, 사용자 수동 자산, 미결정, 문서 로드 순서, 핵심 경로를 남긴다. 기존 `context-save`가 설치되어 있으면 그 스킬의 context-manifest를 사용한다. 존재하지 않는 파일이나 실행하지 않은 테스트를 나열하지 않는다.
