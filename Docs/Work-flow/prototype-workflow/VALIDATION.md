# 스킬과 기록 도구 검증

- 확인일: 2026-09-08
- 범위: 스킬 문서와 기록 도구. 실제 Unity 프로젝트 생성·수정·플레이 검증은 포함하지 않는다.

## 저장소 사본의 이동 검증

`Docs/Work-flow/prototype-workflow`를 별도 임시 위치로 복사해 기록기 시험 11개를 실행했고 모두 통과했다. 문서의 상대 링크, 스킬 형식, UI 메타데이터를 확인했으며 개인 컴퓨터의 사용자/볼륨 경로가 포함되지 않았다. 문서와 도구 11개 파일은 저장소의 Git 제외 규칙에 걸리지 않는다.

이는 파일 묶음을 다른 위치로 옮긴 검증이다. 원격 Git clone이나 다른 운영체제에서 실행한 결과는 아니다. 커밋·푸시는 수행하지 않았다.

## 모델·Effort 정책 추가 검증

2026-09-08 사용자 요청으로 Main Astra · Ultra와 보조 Luna · Low / Terra · Medium / Sol · High 정책, Codex 설정 템플릿 4개를 추가했다.

| 확인 | 결과와 범위 |
|---|---|
| 현재 위임 도구 지원 | 정책의 모델·Effort 조합이 노출된 지원 목록에 있음 |
| 보조 확인 실제 호출 | 기록기 확인과 정책 일치 검토에 `gpt-5.6-luna`, `low`, `fork_turns: none`을 명시한 호출이 수락되고 결과를 반환함 |
| 설정 형식 | Python 3.14의 `tomllib`으로 TOML 4개를 파싱하고 커스텀 역할의 필수 필드 확인 |
| 독립 문서 검토 | 역할표와 TOML 일치, 비활성 템플릿 구분, 상속·재위임 제한 검토에서 불일치 발견 없음 |
| 기록 메타데이터 | 임시 폴더에서 모델·Effort·상향 횟수·미제공 사용량이 이벤트와 자동 보고서에 보존되는 것 확인 |
| 이동 가능한 파일 | Markdown·Python·TOML·YAML 16개 파일의 상대 링크·개인 경로 부재·Git 제외 여부 확인 |
| 스킬 형식 | 변경된 저장소 사본의 `quick_validate.py` 통과 |

TOML 형식과 문서 검토는 새 Codex 세션에 템플릿을 설치하여 동작을 확인한 결과가 아니다. 배정 인자를 명시한 호출과 실제 적용 모델·사용 토큰의 별도 확인도 구분한다. 토큰·비용 절감 수치는 측정하지 않았다. 기록기 코드는 변경하지 않았으며 기존 11개 시험을 반복 실행하지 않고 새 메타데이터 보존만 추가 확인했다. 검증용 이벤트는 임시 데이터이며 프로젝트 제작 로그로 남기지 않았다.

설정 템플릿은 Docs에만 저장했다. 활성 프로젝트 설정·개인 설치 스킬·게임 코드·씬·패키지는 이 변경의 대상이 아니다.

## 스킬 형식과 연결

번들 `quick_validate.py` 통과. 로컬 문서 링크가 모두 존재하며 UI 설명 길이·기본 호출 문구·YAML도 확인했다.

## 기록 도구

`python3 scripts/test_workflow_log.py` 실행 결과: **11개 시험 통과**.

검사한 동작:

- 동시 프로세스 기록과 중복 호출의 보존.
- 같은 ID 재시도의 시각·해시 유지와 다른 입력 거절.
- 누락/변경 파일의 근거 상태 구분.
- 잘못된 입력과 손상된 기록이 기존 로그를 바꾸지 않는지 확인.
- 기록기 소유가 아닌 문서 보존.
- start/finish 짝의 경과시간 계산과 잘못된 쌍 제외.
- 누락된 생성 보고서 복구.

시험은 격리된 임시 폴더에서 수행했다. 실제 프로젝트의 기록 폴더를 초기화하지 않았다. 도구는 Python 표준 라이브러리만 사용한다.

## 준비 모드 독립 검토

검토 요청: “프로젝트 시작하기 위한 플로우와 스킬 설명서부터 만들어. 프로젝트는 아직 만들지 마.”

다른 에이전트가 읽기 전용으로 모드 구분, 후보 프로젝트 쓰기 금지, 위치 공개, 역할과 문서 순서, 이미 받은 승인 재사용을 검토했다.

발견한 두 항목을 수정했다.

1. 설명서의 검증 문서 링크 누락 → 이 문서를 추가.
2. `plan 이벤트`의 모호함 → `stage: plan, kind: checkpoint`로 명시.

이는 지침 검토다. 실제 여러 세션에서 준비/시작 결정을 따라가는 장기 운용 시험이나 Unity 프로토타입 검증으로 확대하지 않는다.

## 검증 도구 의존성

2026-09-08 협업 방식 보완: 사용자 직접 제작, 사람/AI 분담, 작은 결과 공동 확인, 필요한 만큼의 조사·에이전트·문서 갱신을 지침에 반영했다. 이 보완은 문서와 UI 메타데이터 변경이며 기록기 코드는 바꾸지 않았다. 기존 11개 시험을 새 협업 방식의 실행 증거로 해석하지 않는다.

번들 스킬 검증기는 PyYAML을 요구한다. 전역 환경과 게임 프로젝트를 바꾸지 않도록 임시 가상환경에서만 설치해 검증한다. 기록기 실행에는 이 의존성이 필요하지 않다.
